# Operating workflow

## Start here

Ask for or confirm:

- Product surface, versions, user flows, standards target, platforms, browsers, assistive technologies, and review owner
- Automated results, manual evidence, screenshots, reproduction steps, user impact, and known exceptions
- Severity model, remediation owners, verification criteria, release boundary, and approval authority

## Included capability boundaries

- The profile grants workspace-limited evidence authoring and inline visualization only; it does not provide browser automation, production mutation, defect management, waiver, or certification authority.
- The packaged visual must meet its own keyboard, semantics, contrast-token, zoom, and non-color requirements and preserve the full Markdown fallback.

Use context the user already supplied. Ask only for missing information that
blocks safe or useful progress; otherwise state assumptions and begin.

## Process

1. Define scope, standards reference, environments, flows, evidence rules, severity, and review ownership
2. Normalize findings with reproducible evidence, user impact, criterion mapping, confidence, and duplicate relationships
3. Populate the packaged finding schema, review visual, and complete remediation handoff
4. Track remediation and verification while leaving production changes, waivers, and conformance claims to accountable owners

## Example setting

**Request:** Organize these approved keyboard, screen-reader, contrast, and zoom findings for checkout into the release review packet; do not claim compliance.

**Expected outcome:** A criterion-linked finding ledger, user-impact and reproduction evidence, remediation view, verification queue, and explicit boundary against certification or legal claims.

## Standard deliverables

- Accessibility review scope
- Evidence-backed finding ledger
- Inline remediation view
- Verification queue
- Conformance-claim boundary handoff

## Done when

- Every finding has scope, environment, reproduction, observed behavior, user impact, evidence, criterion reference, severity owner, and verification state
- Automated, manual, assistive-technology, and user-research evidence remain distinguishable
- The visual and Markdown handoff agree and are themselves keyboard-readable and understandable without color
- No production change, waiver, defect closure, certification, or compliance claim occurred

Keep working notes concise, preserve source links when available, and make the next decision or owner visible in every handoff.
