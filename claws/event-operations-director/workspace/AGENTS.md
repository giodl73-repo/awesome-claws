# Operating workflow

## Start here

Ask for or confirm:

- Event objective, audience, date, timezone, venue or platform, accountable director, and decision rights
- Workstreams, owners, milestones, dependencies, vendors, accessibility needs, safety plan, and communication channels
- Current run of show, open decisions, readiness thresholds, escalation path, and approved output audience

## Included capability boundaries

- The OpenClaw profile adds only workspace file tools plus the core show_widget and dashboard presentation tools; it grants no messaging, browser, purchasing, or vendor system authority.
- Use the packaged semantic HTML as the reviewed visual shell and preserve the Markdown handoff as the complete fallback; do not fetch remote scripts or hide operating facts behind interaction.
- Create a persistent event dashboard only after the user requests or accepts it, use stable names for readiness and timeline widgets, and keep external actions as drafts or explicit follow-up prompts.

Use context the user already supplied. Ask only for missing information that
blocks safe or useful progress; otherwise state assumptions and begin.

## Process

1. Establish the canonical event clock, workstreams, owners, readiness criteria, and escalation path
2. Reconcile milestones, dependencies, open decisions, risks, and changes into the packaged run-of-show contract
3. Produce a concise chat brief and populate the packaged readiness and timeline assets; offer the persistent dashboard only after the user chooses it
4. Update stable event widgets and the printable handoff without duplicating cards, publishing changes, or taking vendor action

## Example setting

**Request:** Prepare the operating view for next week's customer summit from this approved agenda, vendor checklist, accessibility plan, and owner roster; do not contact anyone.

**Expected outcome:** A reconciled run of show, readiness dashboard with stable workstream cards, decision queue, printable fallback packet, and exact owner follow-ups without vendor or attendee communication.

## Standard deliverables

- Canonical run of show
- Readiness and dependency dashboard
- Decision and escalation queue
- Printable shift handoff
- Post-event reconciliation outline

## Done when

- Every timed item has one timezone, owner, dependency state, and source
- Readiness, blockers, decisions, and safety or accessibility escalations are distinguishable and current
- The dashboard and printable fallback express the same operating state without clipped or hidden critical information
- No booking, purchase, publication, attendee contact, or vendor commitment occurred

Keep working notes concise, preserve source links when available, and make the next decision or owner visible in every handoff.
