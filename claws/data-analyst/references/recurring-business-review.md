# Recurring business review

For one bounded service and authorized audience, produce the actual KPI table,
two-paragraph narrative, evidence references and owner questions using
`templates/recurring-business-review.md`. The original onboarding analysis remains
a separate example; this template does not add execution or data-source access.

Before comparing, bind distinct nonoverlapping periods, source observation dates,
the population, numerator, denominator, target rule, unit and definition revision.
Check the definition contents, not only its label. Keep the original denominator
for each period. A missing, stale, conflicting or audience-restricted source is a
gap, never a zero or a supported trend. Ask for permitted evidence before producing
a complete structured comparison; do not fabricate a numeric metric to satisfy a
schema when no source supports it.

For a comparable pair, show counts and rate together:

- Target-hit rate = 100 * requests meeting target / eligible requests.
- Relative volume change = 100 * (current total - prior total) / prior total.
- Rate change in percentage points = current rate percent - prior rate percent.

A zero denominator has no defined rate. Raw monthly volumes are full-period counts,
not normalized per business day. Explain period lengths when interpreting volumes.
Separate percentage changes from percentage-point changes, and do not claim better
service quality from a larger numerator alone. More requests can produce more hits
with no rate improvement. These descriptive aggregates do not establish causes or
statistical significance; proposed explanations stay hypotheses until evidenced.

Do not pool, rank or reuse adjacent service data with changed definitions. Do not
expose restricted values or references to an audience lacking permission. Ask the
metric owner for a reconciled definition or authorized re-export first. Describe
an exclusion without copying restricted details into the handoff.

Deliver a concise private readout with actionable questions: which definitions
need reconciliation, what evidence could test alternative explanations, and which
decision remains with its owner. Proposed next-period investigation is not an
assignment, approval, customer communication or earnings disclosure.

Use the existing `schemas/analysis-state.schema.json` for the supported structured
analysis. Research Briefing may consume the same permitted table and primary
source references, preserving uncertainty and exclusions. No new coordinator,
financial-reporting authority or customer-communication capability is introduced.

## Worked-example proof

`fixtures/recurring-review-input.example.json` supplies synthetic August/September
counts and a changed adjacent definition. The corresponding analysis-state file
and Markdown readout are generated by repository-only reference calculations.
Tests check this exact source-bound example, including changed counts, definitions,
missing evidence, percentage-point arithmetic and restricted audiences. The exact
example checker deliberately requires the reference wording; it is not a universal
semantic or privacy validator for arbitrary prose. The existing generic schema and
lineage checks alone do not recompute free-form formulas or authenticate exports.
