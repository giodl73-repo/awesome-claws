# Security policy

If you believe you found a security issue in an Awesome Claws package or its
validation tooling, report it privately before opening a public issue.

Use GitHub's **Security** tab to submit a private vulnerability report after
this repository is hosted. If that route is unavailable or you are unsure
which OpenClaw repository owns the issue, email `security@openclaw.ai`.

Include the affected package and revision, reproducible steps, demonstrated
impact, environment details, and suggested remediation. Do not include live
credentials, personal data, or customer content in the report.

Applying a Claw may create an agent, write workspace files, install packages,
configure MCP servers, or schedule work. Report deceptive manifests, catalog
validation gaps, unsafe starter instructions, and failures that hide declared
capabilities. Runtime vulnerability reports should identify the approval,
integrity, path-safety, sandbox, authentication, or policy boundary involved.

For OpenClaw runtime vulnerabilities, follow the
[OpenClaw security policy](https://github.com/openclaw/openclaw/security/policy).
